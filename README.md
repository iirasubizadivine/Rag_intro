# RAG Intro

A minimal Retrieval-Augmented Generation pipeline built with LangChain, Google Gemini, and
ChromaDB. It ingests plain-text company profiles, stores their embeddings in a local vector
database, then retrieves relevant chunks and passes them to Gemini to answer a question.

## How it works

The project is two scripts that run in order.

**1. Ingestion** (`ingestion_pipeline.py`) — reads every `.txt` file in `docs/`, splits each
into 800-character chunks with 200-character overlap, embeds each chunk with
`gemini-embedding-001`, and writes the vectors to `db/chroma_db` using cosine similarity.

**2. Retrieval** (`retrieval_pipeline.py`) — embeds the query, searches the vector store for
the 3 nearest chunks, concatenates them into a prompt, and asks `gemini-3.8-flash` to answer
using only those chunks. If the answer isn't in the retrieved context, the model is instructed
to say so rather than guess.

## Setup

Requires Python 3.10+ and a Gemini API key from
[Google AI Studio](https://aistudio.google.com/apikey).

```bash
python3 -m venv venv
source venv/bin/activate
pip install langchain langchain-community langchain-chroma langchain-google-genai \
            langchain-text-splitters python-dotenv
```

Create a `.env` file in the project root:

```
GOOGLE_API_KEY=your-api-key-here
```

`.env` is listed in `.gitignore` and must stay that way.

## Usage

Add your `.txt` documents to the `docs/` directory, then run:

```bash
python ingestion_pipeline.py
python retrieval_pipeline.py
```

To ask a different question, edit the `query` variable at
`retrieval_pipeline.py:20`.

## Rate limits

The Gemini free tier allows a limited number of embedding requests per day, and ingestion
sends one per chunk. Batches of 50 are submitted with a 65-second pause between them to stay
under the per-minute cap, so ingestion of a large `docs/` folder takes a while. When the
daily quota is exhausted, retrieval fails with a `429 RESOURCE_EXHAUSTED` error and will keep
failing until the quota resets.

## Project layout

```
docs/                       Source .txt documents to index
db/chroma_db/               Persisted vector store (regenerated by ingestion)
ingestion_pipeline.py       Load -> split -> embed -> store
retrieval_pipeline.py       Query -> retrieve -> prompt -> answer
```

`db/chroma_db/` is gitignored because it is derived data. Deleting it is safe; re-running
ingestion rebuilds it from `docs/`. Ingestion also clears the store automatically before
writing, so re-running it never leaves stale chunks behind.

## Notes

- Both scripts use `temperature=0` where applicable for deterministic answers.
- The `collection_metadata` key must be `hnsw:space` for Chroma to apply cosine similarity.
- Both pipelines call `load_dotenv()`, so the API key is read from `.env` at runtime.
